## 유유스 학습실 탭 — 2026-09-09 연결 체크포인트

기존 탭은 유지하고 `유유스 학습실`을 추가했다. contract v2는 기수 생성/상태,
기수별 수강 명단 추가/수정/취소/삭제, 일치 명단을 근거로 한 가입 승인, 현재 기수 배정,
학습실 이용 정지/해제와 변경 기록을 관리한다. 비밀번호·중앙 계정 삭제/정지·Editor
회원 테이블은 이 탭에서 다루지 않는다.

- API는 `academy_api` 하나이며 서버가 별도 academy staff·현재 세션·중앙 ban과 revision을 검사한다. 기존 `uvengers_members.role=admin` UI 통과만으로 새 권한이 생기지 않는다.
- 원문 데이터를 HTML로 넣지 않고 DOM/textContent로 표시한다. 15초 제한·중립적인 결과 미확인 안내·재조회·포커스 복원·계정 변경 시 데이터 폐기를 포함한다.
- 변경 전 확인 창과 사유를 요구한다. 학생에게는 기수 선택을 제공하지 않고, **기수 + 이름 +
  휴대폰 끝 4자리**가 같은 운영 명단 없이는 승인/기수 전환할 수 없다.
- **2026-09-14 원격 DB 직접 변경 (academy 저장소 SQL 체인에 아직 없음 — 옮겨 넣어야 한다).**
  ① 명단 Gmail 을 선택으로: 운영자는 수강생 Gmail 을 미리 알 수 없다(본인이 가입할 때 넣는다).
  `roster_entries.canonical_gmail` nullable, `api()`·`apply_with_roster_match()` 의 Gmail 조건을
  「비어 있으면 통과」로 바꾸고, 연결되는 순간 가입자의 Gmail 을 명단에 적는다. Gmail 이 든 기존 줄은
  예전과 똑같이 대조한다. 같은 조건이 둘 이상이면 자동 승인하지 않는다(`ambiguous_cohort`·`identity_collision`).
  ② `roster_delete`: 취소됐고 계정과 연결된 적 없으며 `memberships` 가 가리키지 않는 줄만 영구 삭제한다.
  `memberships` 외래키 하나가 `ON DELETE CASCADE` 라 이 거부 조건이 없으면 수강 등록이 딸려 지워진다.
  삭제해도 `audit_events` 에 이름·끝 4자리·기수·사유가 남는다. 실측은 모두 되돌림 거래로 했다 —
  취소 줄 삭제 ok / 쓰는 줄·연결된 줄 거부 / 개정 번호 틀리면 거부 / 적용 전후 자료 수 동일.
- 기수·명단·승인 작업은 중앙 계정/Editor 권한을 바꾸지 않는다. 사용자의 운영 결정에 따라
  이 탭은 별도 TOTP를 요구하지 않고 기존 RAION Admin 로그인과 명시적 academy staff 등록을
  모두 통과한 관리자만 사용한다.
- SQL 계약은 academy 저장소의 `database/academy/` 독립 체인이다. 기존 root Supabase migrations를 shared 프로젝트에 적용하지 않는다.
- 원격 Academy v1/v2/v3 DB/API, 정확한 관리자 권한과 1기 seed는 적용·읽기 검증을 마쳤다. 기존 페이지의 unsafe HTML 출력·정지 관리자 처리·원격 세션 경합·백업·기존 제품 회귀는 실제 수강생 데이터 투입 전 차단 항목이다.
- 관리자로 쓸 정확한 중앙 Auth UUID와 기수를 검증한 뒤 승인된 계정만 등록한다. 기존 관리자 전체에 학습실 권한을 자동 부여하지 않는다.
- 화면은 기존 관리자의 카드·버튼·금색 강조 체계를 쓴다. Academy 내부 탭을 두지 않는다. **카드는 일의 순서로 선다(2026-09-14)**: 준비(좌 `기수 관리` · 우 `수강 명단 관리`, 2열, 1180px 아래는 위아래) → 요약 → `가입 승인 대기` → `수강생 관리`. 수강생 추가는 이름·끝 4자리·기수가 필수이고 Gmail 은 선택이며, `엑셀 양식 받기`·`엑셀로 여러 명`(이름·휴대폰 끝 4자리·기수 세 칸)으로 대량 등록한다. 기수는 **왼쪽 기수 카드의 「N명 명단 보기」로만** 고르고(다시 누르면 전체), 같은 기수를 두 번 고르던 `기수별 보기` 드롭다운은 없앴다. 등록 명단은 한 사람 한 줄 표(이름·끝 4자리·Gmail·기수·상태·관리)로 420px 상자 안에서 세로로 구르고 머리글이 붙어 있으며, 이름·끝 4자리·Gmail 로 찾는다. 각 줄의 `수정`·`취소`·`삭제` 입력은 그 줄 바로 아래 칸에서 열리고, 사유가 비면 까닭을 그 칸 바로 아래에서 칸 이름 그대로 말한다. 새 명단을 저장하면 해당 기수 필터로 자동 전환한다. 이미 계정과 연결된 명단은 무결성을 위해 직접 바꾸지 않고 `수강생 관리에서 변경`으로 안내한다. 저장·취소 뒤에는 서버 목록을 다시 불러오며 변경 사유·확인·revision·audit를 생략하지 않는다. 가입 신청·수강생 계정·기수 운영 설정은 각각 별도 카드로 분리한다. DB의 세부 기수 상태와 내부 참조값은 계약에 유지하되 일반 관리 화면에는 노출하지 않는다. 기수 주소 코드는 기수 번호에서 자동 생성하고, 취소된 명단은 접힌 보조 목록으로 두며 그중 계정과 연결된 적 없는 줄만 `삭제`가 보인다. 페이지 전체 검색·정렬 도구는 두지 않고 실제 수강생이 여러 명일 때 `수강생 관리` 안에서만 이름·Gmail·기수·상태를 정렬한다. 전역 변경 기록 화면은 두지 않고 각 계정의 `최근 이력`에서 관련 감사 로그만 확인하며 v5의 `application_auto_approved`는 `명단 자동 확인`으로 표시한다. 한 페이지에서 최대 100건씩 이동한다. 유벤져스의 넓은 가입·멤버 표는 문서 폭을 늘리지 않는 레이블 있는 내부 스크롤 영역에 둔다.
